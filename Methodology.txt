Methodology: Time-aware LoRA Training and RAG-assisted Inference

This implementation contains two connected stages:

1. `lora_train_time.py` fine-tunes Qwen3-VL-4B-Instruct with LoRA so the model can better answer multiple-choice egocentric video questions with explicit temporal information.
2. `infer_time_codex_loraAux.py` performs test-time inference with domain-adaptive LoRA selection and optional CholecT50 retrieval-augmented context for surgical videos.


1. Time-aware LoRA training

The training script builds a supervised fine-tuning dataset from EgoCross support-set samples. Each sample is expected to contain image frame paths and a two-turn message structure: the user message contains the visual question and answer options, while the assistant message contains the correct option letter.

For each training sample, the script first parses the question text and options from the original user content. It removes the original `<image>` placeholder and extracts multiple-choice options matching `A/B/C/D` style prefixes. The final instruction prompt asks the model to solve the visual multiple-choice question and to output only one uppercase letter among `A`, `B`, `C`, and `D`.

Video frames are uniformly sampled up to `--max-frames`. If the clip has fewer frames than the limit, all frames are used; otherwise the script selects evenly spaced indices across the full clip. Each image is opened as RGB and resized by thumbnailing to `--image-max-side` to reduce memory pressure.

The core temporal design is to insert an explicit timestamp marker before every image:

`<time_start> t <time_end>`

The timestamp `t` is computed from the frame order and the sample FPS. Most videos use the default FPS, while surgical-domain samples and selected CholecTrack20 videos use 1 FPS. This creates a multimodal conversation in which the model sees alternating time text and image frames, followed by the question and answer options. The model therefore learns not only visual recognition, but also the temporal position of each observed frame.

The processor applies the Qwen chat template and converts the text-image conversation into model inputs. The target answer is tokenized separately and appended after the prompt. Labels are masked with `-100` for all prompt tokens so the loss is computed only on the answer token and EOS token. Samples exceeding `--max-length` are rejected with an explicit runtime error, which prevents silent truncation of visual-question context.

The base model is loaded from `--model-path` as `Qwen3VLForConditionalGeneration`. By default, the script uses 4-bit NF4 quantization through BitsAndBytes, double quantization, fp16 compute, gradient checkpointing, and the paged 8-bit AdamW optimizer. This is a QLoRA-style setup intended to make fine-tuning feasible on limited GPU memory.

LoRA adapters are attached to the causal language modeling task. The default target modules are:

`q_proj,k_proj,v_proj,o_proj,gate_proj,up_proj,down_proj`

This covers attention projections and MLP projections, allowing the adapter to modify both visual-language attention behavior and answer-generation behavior while keeping the frozen base model mostly unchanged. The default LoRA configuration uses rank 32, alpha 64, and dropout 0.05.

The custom collator pads `input_ids`, `attention_mask`, and `labels`, concatenates visual `pixel_values`, and concatenates `image_grid_thw`. Training is handled by Hugging Face `Trainer`, with configurable epochs, batch size, gradient accumulation, learning rate, warmup, checkpoint frequency, and seed. At the end of training, the script saves the LoRA adapter together with the processor and tokenizer into the output directory.


2. RAG-assisted and domain-adaptive inference

The inference script loads the EgoCross testbed JSON, a submission template, the Qwen3-VL base model, and two LoRA adapters. Adapter 1 is treated as the general VQA adapter. Adapter 2 is treated as an EgoPet-specific expert adapter. During inference, the script selects the model behavior by dataset:

- `CholecTrack20` and `EgoSurgery`: disable LoRA and use the base model.
- `EgoPet`: use the `egopet_expert` adapter.
- Other datasets: use the `general_vqa` adapter.

This routing is a simple domain adaptation strategy. It avoids forcing one adapter to handle domains where it may hurt performance, while still using specialized adapters where they are expected to help.

For each test sample, frame paths are resolved under the dataset root and uniformly sampled up to `--max-frames`. Images are converted to RGB and resized to a maximum side of 1024 pixels. The FPS is determined from the dataset: EgoSurgery uses 1 FPS, specific CholecTrack20 videos such as VID25 and VID111 use 1 FPS, and other samples default to 0.5 FPS.

The inference script also inserts explicit time markers before every current-video frame. Unlike the training script, timestamps are derived from the original frame index parsed from the frame filename, normalized relative to the first selected frame:

`timestamp = (frame_idx - start_idx) / fps`

This preserves the temporal spacing implied by original frame numbers, rather than assuming selected frames are evenly spaced after sampling.


3. CholecT50 retrieval-augmented context

For CholecTrack20 samples, the script can add retrieval-augmented knowledge from CholecT50 annotations unless `--disable-rag` is set.

The RAG index is built by reading `VID*.json` annotation files under `--rag-root`. For each annotated frame, the script extracts:

- surgical instruments
- surgical phase labels
- triplet/action labels
- verbs and targets
- approximate spatial regions computed from bounding boxes

Bounding boxes are converted into coarse image regions such as `top-left`, `center`, or `bottom-right`. Each frame becomes a compact text summary containing video id, frame id, phase, instruments, actions, and regions. The script also stores tokenized labels for retrieval.

Retrieval is lexical and deterministic. The query is formed from the current sample's question text, question type, primary category, and options. Each CholecT50 record receives a score based on token overlap plus stronger phrase matches against known labels. If the question mentions "next phase", phase-related records receive a small bonus. The top `--rag-top-k` records are selected.

The retrieved records are converted into a text context that includes:

- a warning that CholecT50 annotations are only reference knowledge
- known surgical instruments
- observed surgical phase order
- the most relevant annotated reference-frame summaries

Optionally, up to `--rag-visual-examples` retrieved CholecT50 reference images are prepended to the multimodal prompt. Each such image is labeled as a RAG reference image and is explicitly marked as not being part of the current question video. This is intended to calibrate recognition of surgical instruments, actions, phases, and regions without confusing retrieved examples with the current input.


4. Final prompt and answer extraction

The final inference message is assembled in this order:

1. optional CholecT50 RAG text context
2. optional CholecT50 RAG reference images
3. a separator indicating that current EgoCross video frames begin
4. current-video frames with `<time_start> ... <time_end>` markers
5. the multiple-choice question prompt

The prompt instructs the model to answer only with one uppercase option letter. Generation uses configurable `--max-new-tokens`, `--temperature`, and `--top-p`. After decoding, the script extracts the first valid `A/B/C/D` answer with a regular expression. If the model produces no usable option, the parsed answer becomes `None`.

Predictions are written incrementally to the output JSON after each sample. This makes the run partially recoverable if inference is interrupted.


5. Overall method

The overall method combines three mechanisms:

- Temporal grounding: every frame is paired with an explicit timestamp marker, allowing the model to reason about event order and elapsed time.
- Parameter-efficient specialization: LoRA/QLoRA adapts Qwen3-VL to EgoCross-style multiple-choice visual QA without fully fine-tuning the base model.
- Domain-aware inference: adapter routing and CholecT50 RAG inject domain-specific surgical knowledge only where it is expected to help.

Together, these choices target egocentric video QA where correct answers often depend on both visual evidence and temporal context, while keeping training and inference practical for a large multimodal model.
